# เว็บไซต์ธนากรฟิชชิ่งและระบบหลังบ้าน

เว็บไซต์หลักและหลังบ้านที่ `index.html`, `15.html`, `admin.html` ใช้เซิร์ฟเวอร์ Node.js ของเราเองและเก็บข้อมูลในเครื่องที่รันเซิร์ฟเวอร์ รายละเอียดการเริ่มใช้อยู่ในหัวข้อ “ระบบหน้าเว็บและหลังบ้านที่เก็บข้อมูลในเครื่องเรา” ด้านล่าง ส่วนโฟลเดอร์ `opo/` และการตั้งค่า LINE แบบ Vercel ที่อธิบายด้านล่างเป็นระบบเดิมแยกต่างหาก

## ระบบ LINE เดิมบน Vercel (แยกจากเว็บที่รันเอง)

1. ใน LINE Developers สร้าง LINE Login channel และ Messaging API channel ให้อยู่ใน Provider เดียวกัน แล้วเชื่อม Messaging API channel กับ LINE Official Account `@634lfegy`
2. เพิ่ม LIFF app ใน LINE Login channel โดยตั้ง Endpoint URL เป็น `https://<โดเมน-vercel>/line-send.html` และเปิด scope `openid` กับ `profile`
3. เพิ่มเพื่อน LINE Official Account จากบัญชีที่จะทดสอบ และตรวจว่าเปิดใช้ Messaging API แล้ว
4. Deploy โฟลเดอร์นี้เป็น Vercel project root
5. ตั้ง Environment Variables ใน Vercel Project Settings:
   - `LINE_LIFF_ID`: LIFF ID จาก LINE Developers (เป็นข้อมูลสาธารณะ)
   - `LINE_LOGIN_CHANNEL_ID`: Channel ID ของ LINE Login channel ที่สร้าง LIFF
   - `LINE_CHANNEL_ACCESS_TOKEN`: Channel access token ของ Messaging API channel (เก็บเป็น Secret ใน Vercel เท่านั้น ห้ามใส่ใน HTML/JavaScript)
6. Redeploy หลังบันทึก Environment Variables

## พฤติกรรมการส่ง

เมื่อผู้ใช้เลือกสินค้า หน้าเว็บจะเปิด LIFF หลังเอฟเฟกต์จบ LIFF จะยืนยัน LINE ID token กับ backend แล้ว backend ส่งรูปและชื่อสินค้าเข้า LINE ของผู้ใช้ผ่าน Messaging API โดยไม่ส่ง token ไปยังเบราว์เซอร์

การส่ง push ทำได้เมื่อ LINE อนุญาตให้ Official Account ส่งถึงผู้ใช้นั้น โดยทั่วไปผู้ใช้ต้องเพิ่มบัญชีร้านเป็นเพื่อนและไม่บล็อกบัญชี รูปจาก Google Drive ต้องตั้งสิทธิ์ “ทุกคนที่มีลิงก์”; backend จะนำรูปผ่าน endpoint ที่ตรวจชนิดไฟล์และขนาดก่อนส่งต่อ ส่วนรูปในโปรเจกต์จะใช้โดเมน Vercel ของร้าน

การทดสอบในเครื่องด้วย `file://` จะเรียก API/LIFF ไม่ได้ ต้อง deploy บน HTTPS หรือใช้ Vercel CLI และตั้งค่า LIFF endpoint ให้ตรงกับ URL ที่ทดสอบ

## ระบบหน้าเว็บและหลังบ้านที่เก็บข้อมูลในเครื่องเรา

ระบบหลังบ้านใหม่นี้ใช้ Node.js และไฟล์ JSON/รูปภาพบนคอมพิวเตอร์เครื่องที่เปิดเซิร์ฟเวอร์ โดยไม่ใช้ Supabase, Firebase หรือบริการเก็บไฟล์ภายนอก ข้อมูลสินค้าจะส่งไปแสดงบนหน้าเว็บที่เสิร์ฟจากเซิร์ฟเวอร์เครื่องเดียวกัน

1. ติดตั้ง Node.js 20 ขึ้นไป
2. คัดลอก `.env.example` เป็น `.env` แล้วกำหนด `ADMIN_PASSWORD` เป็นรหัสผ่านยาวอย่างน้อย 12 ตัวอักษร อีเมลผู้ดูแลหลักตั้งต้นคือ `mokll0081@gmail.com`
3. เปิด PowerShell ในโฟลเดอร์โปรเจกต์ แล้วรัน `node server.js`
4. เปิดหน้าเว็บที่ `http://localhost:8080` และหลังบ้านที่ `http://localhost:8080/admin`
5. ข้อมูลบัญชีจะเก็บใน `data/users.json` และรายการสินค้า/รูปจะเก็บในโฟลเดอร์ `data/` อย่าลบหรือเผยแพร่โฟลเดอร์นี้ และควรสำรองข้อมูลเป็นระยะ

ในครั้งแรกที่สร้างบัญชีสำเร็จ เซิร์ฟเวอร์จะลบรหัสผ่านตั้งต้นออกจาก `.env` และเก็บเฉพาะค่า hash ใน `data/users.json` หากย้ายเครื่อง ให้สำรองทั้ง `data/` และไฟล์ `.env` ส่วนรหัสผ่านผู้ดูแลใหม่ที่สร้างในหลังบ้านต้องยาวอย่างน้อย 12 ตัวอักษร

**การใช้จากนอกบ้าน:** ต้องเปิดคอมและเซิร์ฟเวอร์ไว้ รวมถึงตั้งค่าเราเตอร์/ไฟร์วอลล์และ HTTPS ด้วยโดเมนกับใบรับรองที่เชื่อถือได้ เซิร์ฟเวอร์ปฏิเสธการล็อกอินจากอินเทอร์เน็ตผ่าน HTTP เพื่อไม่ส่งรหัสผ่านแบบไม่เข้ารหัส อย่าเปิดพอร์ตสู่สาธารณะจนกว่าจะตั้ง HTTPS เรียบร้อย หน้า GitHub Pages เดิมเป็นเว็บ static และจะไม่เห็นข้อมูลจากเครื่องนี้โดยอัตโนมัติ ต้องให้ลูกค้าเปิด URL ของเซิร์ฟเวอร์นี้

ผู้ดูแลหลักล็อกอินด้วยอีเมลและรหัสผ่านของเว็บเอง สามารถสร้างบัญชีผู้ดูแลและผู้แก้ไขได้ ผู้ดูแลสร้างผู้แก้ไขได้ แต่มีเพียงผู้ดูแลหลักที่สร้างผู้ดูแลคนอื่นได้
